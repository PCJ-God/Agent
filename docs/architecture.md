# 架构设计文档

## 系统概述

智能教学助手 Agent 系统是一个基于大语言模型的端到端智能教学辅助平台。系统采用 AgentScope 生产级框架,集成 Function Calling、MCP 协议、ReAct 规划执行、多Agent协作、Memory记忆管理、Skill技能固化和评测驱动开发等核心技术,为教学场景提供完整的智能化解决方案。

## 设计原则

### 1. 模块化设计
- 各核心功能 (工具调用、规划、记忆、技能、评测) 独立为模块
- 模块之间通过清晰接口交互,可单独替换和升级

### 2. 标准化协议
- 采用 MCP (Model Context Protocol) 实现工具的标准化管理
- 工具提供方与消费方解耦,支持工具热插拔

### 3. 评测驱动
- 建立完善的评测体系,确保系统性能可量化、可持续改进
- 端到端评测 + 白盒化分析,覆盖黑盒输出和内部流程

### 4. 可扩展性
- 通过 Skill 机制将验证过的工作流固化为可复用技能
- 通过 Memory 机制积累跨会话经验,支持持续优化

## 核心模块设计

### 1. Agent 编排层

**职责**: 管理多个Agent实例,负责任务分解、分配和编排

**关键组件**:
- **ReActAgent**: 基础的思考-行动-观察循环
- **ResearchAgent**: 专注于资料搜集和整理
- **ReviewAgent**: 专注于质量审查和评估
- **SummaryAgent**: 专注于信息整合和汇总
- **CoordinatorAgent**: 负责任务分解和流程编排

**交互模式**:
- **顺序编排**: 按依赖关系依次执行
- **条件分支**: 根据中间结果决定流程走向
- **并行执行**: 多个Agent独立执行,最后汇总

### 2. 核心服务层

#### 2.1 Tool Calling Service

**职责**: 管理工具的定义、注册、调用和结果解析

**关键特性**:
- Function Calling 标准协议支持
- JSON Schema 参数验证
- 引导-校验-重试闭环
- 工具执行日志和监控

#### 2.2 Memory Management

**职责**: 管理短期和长期记忆,支持经验积累和快速召回

**架构**:
- **短期记忆**: Agent框架内置,管理当前会话上下文
- **长期记忆**: 持久化存储,跨会话经验积累
- **主动管理**: Agent自主判断保存时机和内容

#### 2.3 Skill Registry

**职责**: 管理可复用技能的注册、发现和调用

**设计模式**:
- 技能基类 (BaseSkill): 定义统一接口
- 技能实现: 具体业务逻辑
- 技能注册表: 管理所有可用技能

#### 2.4 Evaluation Engine

**职责**: 提供端到端评测和白盒化分析能力

**评测维度**:
- 输出质量 (1-5分)
- 工具调用准确率 (1-5分)
- 执行效率 (1-5分)
- 综合评分

#### 2.5 Planning Engine

**职责**: 支持复杂任务的自主规划和执行

**规划模式**:
- **反思模式**: 执行过程中检查质量
- **自主规划**: 生成执行计划并按步骤执行

### 3. MCP 协议层

**职责**: 实现工具的标准化管理和动态发现

**传输模式**:
- **stdio**: 本地调试,进程间通信
- **Streamable HTTP**: 生产环境,远程服务

**工作流程**:
1. Agent 启动时,MCP Client 连接 MCP Server
2. Client 拉取 Server 声明的工具清单
3. Agent 将工具注册到工具箱
4. 后续任务中按需调用工具

## 数据流

### 典型任务执行流程

```
用户请求
    ↓
[1] CoordinatorAgent 接收请求,分析任务
    ↓
[2] 生成执行计划: Research → Review → Summary
    ↓
[3] ResearchAgent 执行资料搜集
    ├─ 调用 MCP WebSearch 工具
    ├─ 调用 MCP ArxivSearch 工具
    └─ 整理搜索结果
    ↓
[4] ReviewAgent 审查 ResearchAgent 的输出
    ├─ 检查完整性
    ├─ 检查准确性
    └─ 生成审查报告
    ↓
[5] SummaryAgent 整合研究和审查结果
    └─ 生成最终输出
    ↓
[6] MemoryManager 保存本次经验
    ├─ 保存工具调用经验
    ├─ 保存工作流程模板
    └─ 更新访问统计
    ↓
[7] 返回最终结果给用户
```

## 技术选型

### 核心框架

| 技术 | 用途 | 选型理由 |
|------|------|---------|
| **AgentScope** | Agent 框架 | 生产级ReAct Agent,内置工具管理和MCP支持 |
| **DashScope API** | 大模型服务 | 通义千问模型,支持Function Calling |
| **MCP SDK** | 工具协议 | 标准化工具管理,解耦工具定义与使用 |
| **Pydantic** | 数据验证 | 结构化输出验证,确保参数准确 |

### 辅助技术

| 技术 | 用途 | 选型理由 |
|------|------|---------|
| **asyncio** | 异步编程 | 高并发工具调用,提升性能 |
| **PyYAML** | 配置管理 | 清晰的配置文件格式 |
| **Loguru** | 日志管理 | 简洁的日志API,易于调试 |
| **Rich** | 终端美化 | 友好的CLI输出展示 |

### 测试与评测

| 技术 | 用途 | 选型理由 |
|------|------|---------|
| **pytest** | 单元测试 | Python标准测试框架 |
| **pytest-asyncio** | 异步测试 | 支持异步代码测试 |
| **pytest-cov** | 覆盖率 | 测试覆盖率报告 |

## 安全考虑

### API Key 管理

- 使用环境变量存储敏感信息 (如 `DASHSCOPE_API_KEY`)
- 不要将密钥硬编码在代码中
- 使用 `.env` 文件管理环境变量

### 工具调用权限

- 为不同Agent配置不同的工具访问权限
- 对敏感工具添加鉴权检查
- 记录所有工具调用日志

### 数据隐私

- 不存储用户敏感信息
- 对长期记忆中的数据进行脱敏处理
- 定期清理过期的记忆数据

## 性能优化

### 并发策略

- 使用 asyncio 实现高并发工具调用
- 多个独立任务并行执行
- 共享工具调用结果 (避免重复搜索)

### 缓存策略

- 缓存常见的搜索结果
- 缓存技能的中间结果
- 设置合理的缓存过期时间

### 资源限制

- 设置 Agent 最大循环次数 (防止无限循环)
- 设置工具调用超时时间 (防止长时间等待)
- 限制记忆存储大小 (防止存储膨胀)
